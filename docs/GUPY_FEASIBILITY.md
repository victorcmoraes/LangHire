# Gupy feasibility checkpoint

Checked on 2026-10-28. Phase 0 found a source restriction, so this checkpoint
does not enable collection or assisted applications.

The [candidate terms, version 2026-07-01](https://www.gupy.io/termos-de-uso-recrutamento-e-selecao-candidatos)
restrict aggregation/copying of platform content. Following the execution prompt's
stop-on-restriction rule, no jobs were scraped, no undocumented search endpoints
were probed, and no candidate login or automated application was attempted.

The [official API authentication guide](https://developers.gupy.io/v2.0/docs/autentica%C3%A7%C3%A3o-recrutamento-sele%C3%A7%C3%A3o)
requires a bearer token generated by a company administrator with API-token
permissions. An employer integration API does not establish an anonymous job
search API for a personal candidate tool. No suitable authorized search source
was confirmed.

The terms describe an email/password account and a shared candidate profile.
They also describe a separate quick-application flow that does not require login;
the plan's login assumption therefore does not cover every vacancy. Custom
questions, online assessments and video stages vary by employer. Assessments and
videos must remain human tasks. The user must fill and review any shared profile.

Because source permission failed the first gate, browser-profile login,
CAPTCHA/rate-limit behavior and application confirmations were not tested here.
Do not infer that login works or that the absence of observations means the
platform has no protection. No phase 1 collector or submission adapter was added.

Decision recorded on 2026-10-28: defer Gupy until an authorized source is
available. Gupy remains outside collection and application flows. The original
assisted-versus-collection choice cannot proceed against the restricted source
identified in this review.

An authorized feed or explicit platform permission would allow revisiting the
collection gate. Assisted applications would still require browser validation,
human-only assessment handling and a separately approved pilot. Platform access
and submission support remain unchanged by this document.

## Decision update — 2026-11-05

The user reviewed the restriction above and chose to collect from Gupy anyway, for personal use and low
volume, accepting the terms risk. Collection reads only public pages, without login:

- `portal.gupy.io/job-search/...` (server-rendered search), via `cli.external sources --source gupy`
- each company's career page `{company}.gupy.io` and posting `{company}.gupy.io/jobs/{id}`, via `refresh_board('gupy', company)`

Applications stay human. The Apply Assist extension opens `/candidates/jobs/{id}/apply`. The candidate logs
in with their own Gupy account and finalizes the application. The extension fills only empty controls in each
step. Assessments and video stages remain human tasks. Nothing submits automatically, and the automatic
runner (`run_external`) still refuses Gupy.
